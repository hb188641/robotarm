# 호출어 기반 음성 모터 제어

작성일: 2026-10-17
상태: 대화에서 구조 승인됨. 이 문서 검토 후 구현 계획 작성.

## 목표와 범위

사용자가 로컬 마이크에 “로봇”이라고 말하면 명령을 녹음하고,
OpenAI 음성 인식 모델(1번), JSON 변환 LLM(2번)을 순서대로 호출해
지정한 번호의 모터를 기존 REST 서버로 움직인다.

예: “로봇” → 준비 신호 → “3번 모터 위치 2200으로 이동”
→ 전사 → 검증된 모터 명령 → motor_3 이동.

모터는 기존 서버의 motor_1~motor_6이며 위치 단위는 raw tick(0~4095)이다.
모터 번호만 말하고 위치를 생략한 요청은 실행하지 않고 구체적인 위치를 요청한다.
이번 범위는 절대 위치 지정이다. 상대 회전, 각도 변환, 집기, 카메라 인식,
자율 동작 시퀀스는 포함하지 않는다. 기존 voice_pick 초안과 별도 기능이다.

## 선택한 접근

- 로컬 faster-whisper 다국어 모델로 한국어 호출어를 감지한다.
  기본 모델은 small, CPU int8이며 모델 이름을 설정으로 변경할 수 있다.
  모델 파일은 최초에 내려받고, 이후 호출어 추론은 로컬에서 수행한다.
  전용 키워드 탐지기보다 계산량과 지연이 크지만 별도 한국어 호출어 학습이나
  외부 호출어 서비스 키 없이 구현할 수 있다. 실제 인식률과 지연은 마이크 시험으로 확인한다.
- 클라우드 1번 모델 기본값은 gpt-4o-mini-transcribe,
  2번 모델 기본값은 구조화 출력을 지원하는 gpt-4o-mini이다.
  두 이름은 독립 설정값이다. 사용자가 말한 1번/2번은 단계 번호로 해석한다.
- 기존 Flask REST 서버와 Python 클라이언트를 재사용한다.
  음성 기능은 새 TITI/voice_motor 패키지와 독립 의존성 파일로 제공한다.

## 데이터 흐름과 모듈

1. 마이크 입력을 한 스트림에서 읽는다. 호출어 대기 중 오디오는 로컬에서만 처리한다.
2. 로컬 모델이 독립된 호출어 “로봇”을 인식하면 준비 신호를 출력하고 녹음 상태로 전환한다.
   사용법은 호출어를 말하고 준비 신호 이후 명령을 말하는 두 발화 방식이다.
   같은 발화에서 바로 이어 말하는 방식은 초기 버전의 보장 범위가 아니다.
3. 시작 무음 제한, 종료 무음 길이, 최대 녹음 길이를 적용한다.
   말이 없거나 너무 짧으면 API를 호출하지 않고 다시 대기한다.
4. 명령 WAV를 1번 모델에 전달한다. 전사는 한국어를 지정한다.
5. 전사 텍스트를 2번 모델에 전달해 엄격한 JSON 스키마로 변환한다.
6. 로컬 검증 후 기존 클라이언트의 여러개이동으로 REST 요청을 보낸다.
7. 실제 위치를 조회해 도달 여부를 확인하고 완료 또는 실패를 출력한 뒤 다시 대기한다.

구성은 config(설정과 env), audio(마이크·구간 녹음), wake(로컬 인식),
intent(OpenAI 2단계), commands(JSON 검증), executor(REST 실행·도달 확인),
main(CLI와 상태 전이)로 나눈다. import만으로 마이크, 네트워크, 모터를 열지 않는다.

## 명령 계약

LLM 출력 예:

```json
{"action":"move","targets":[{"motor":3,"position":2200}]}
```

action은 move 또는 unknown이다. move는 motor 1~6과 정수 position 0~4095를
갖는 targets 1~6개가 필요하며 중복 모터는 거부한다. unknown은 빈 targets이다.
불필요한 필드, bool/실수/문자열 수치, 잘못된 번호나 범위, 알 수 없는 action은 거부한다.
불명확한 요청에서 모델이 번호나 위치를 추정하지 않도록 프롬프트에 명시한다.
검증 후 REST body는 {"motor_3":2200}처럼 변환한다.

## 설정과 실행

OPENAI_API_KEY는 프로세스 환경변수 우선, 명시한 --env-file,
저장소 루트 .env, 상위 /Users/hwangboyun/robot/.env 순서로 선택한다.
명시적으로 지정한 env 파일이 없으면 오류로 처리한다. 비밀 값은 출력하거나 복사하지 않는다.
모델, 호출어, 마이크 장치, REST 주소, 녹음 제한은 설정/CLI로 변경할 수 있게 한다.

--dry-run은 전사와 JSON 변환을 수행하고 검증된 목표만 출력하며 모터 요청은 보내지 않는다.
--text는 마이크와 호출어 없이 텍스트→JSON 경로를 점검한다.
--audio-file은 녹음 WAV→전사→JSON 경로를 점검한다.
실제 모터 실행은 명시적 --execute로 선택한다.
기본 실행은 dry-run이다. README에 설치, 모델 최초 다운로드, 서버 시작과
dry-run/execute 사용법을 작성한다.

## 오류와 실행 경계

API 오류, 거절, 잘린 출력, 잘못된 JSON은 모터 요청 없이 실패로 보고한다.
OpenAI와 모터 HTTP 요청에는 타임아웃을 둔다. 모터 쓰기는 자동 재시도하지 않는다.
응답 유실은 이동 성공 여부가 불명확하다고 보고한다.
범위 밖 값을 조용히 보정하거나 토크를 자동으로 켜지 않는다.
REST 서버의 raw 위치 전체 범위가 기계적으로 안전한 관절 범위를 의미하지 않으므로
실행 시 관절별 min/max와 명령당 최대 변화량을 설정 파일로 제공하고,
현재 위치를 기준으로 모든 목표를 미리 검사한다. 하드웨어용 제한 파일 없이
--execute하면 실행을 거부하며, dry-run은 제한 파일 없이 가능하다.
도달 확인에는 타임아웃을 두고 실제 위치를 확인하기 전에는 완료로 표시하지 않는다.
Ctrl-C는 새로운 목표 전송을 중단한다. 이미 보낸 위치 명령을 취소하거나
기계적 비상 정지를 보장하지 않으며, 별도의 음성 비상 정지 기능도 이번 범위에 없다.
종료 때 토크를 임의로 해제해 팔을 떨어뜨리지 않는다.

## 검증과 완료 기준

- 가짜 OpenAI 클라이언트와 모터 클라이언트로 2단계 호출 순서와 JSON→REST 매핑 검증.
- 잘못된 명령, API 실패, 무음, 중복 번호, 기계 제한 초과 시 모터 요청 0회 검증.
- 녹음 종료·최대 길이, 호출어 오탐 방지, 모델 지연 중 입력 적체 처리 검증.
- dry-run 및 import가 실제 모터에 접근하지 않는지 검증.
- 기존 pytest 회귀와 문법·정적 오류 검사.
- 키로 실제 텍스트→JSON 연결 시험은 모터를 움직이지 않는 dry-run으로 수행.
- 마이크 호출어→녹음, 실제 음성 인식, 실제 모터 이동은 각각 별도 증거로 보고한다.
  하드웨어나 권한이 없으면 해당 구간이 미검증임을 명시한다.

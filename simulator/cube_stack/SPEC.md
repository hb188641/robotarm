# cube_stack — 3색 큐브 쌓기 시뮬레이터 스펙

작성일: 2026-11-21 · 상태: **v1 구현 완료** (MuJoCo 전용)

## 1. 목표

SO-101 로봇팔(MuJoCo 시뮬레이션)이 바닥(책상)에 흩어진 **빨강·노랑·파랑 큐브 3개**를
카메라로 찾아서 **한 곳에 3층으로 쌓는다.**

- **학습(딥러닝·강화학습·모방학습) 없음.** 인식은 OpenCV 고전 영상처리(HSV 임계값, 윤곽선,
  모멘트, minAreaRect)만 쓴다.
- 동작은 기존 기하학 IK(`TITI/voice_motor/kinematics.py`)와 규칙 기반 상태 기계로 한다.
- 결정 코드는 **실제 팔도 알 수 있는 정보만** 쓴다: 두 카메라 영상, 관절 위치, 그리퍼 부하.
  물리엔진의 큐브 실제 위치는 **채점(심판)에만** 쓴다 (테스트로 강제).

### 성공 기준과 결과

| 항목 | 기준 | v1 결과 (시드 1, 50회) |
| --- | --- | --- |
| 최종 상태 | 지정 순서로 3층, 2초 뒤에도 서 있음 | **50/50** |
| 정렬 | 위·아래 중심 오차 ≤ 6 mm, 각도 ≤ 10° | 1.8~3.7 mm, ≤ 1° |
| 성공률 | ≥ 90% | 100% |
| 판정 정직성 | 로봇 판단 ≠ 심판 ≤ 2% | 0/50 |
| 시간 | ≤ 60초 (시뮬레이션 시간) | 대부분 33~37초 |

## 2. 범위

**포함:** `simulator/cube_stack/` 새 폴더 (기존 `simulator/sim/`은 import만 하고 수정하지 않음),
3색 큐브 장면, **허공의 고정 카메라**, 손목 카메라, 3색 검출, 쌓기 상태 기계, 심판,
MuJoCo 창·헤드리스 실행, 테스트.

**제외:** 실제 팔 구동, 학습 기반 무엇이든.

**추가 (v1.1):** 브라우저 패널 `/stack/` — 집기 패널과 한 서버·한 포트(기본 80)에서, 홈 `/`에서 고름 (`stack/world.py`, `simulator/web/stack.*`).

## 4. 장면

- 책상: 기존 회색-베이지 체커 (채도 낮음)
- 큐브: 한 변 25 mm, 20 g. 빨강 `0.85 0.05 0.05`, 노랑 `0.95 0.85 0.05`, 파랑 `0.05 0.20 0.85`
- **고정 카메라 `top`:** (0.44, 0, 0.56) m 허공에서 (0.17, 0, 0)을 내려다봄, fovy 44°, 640×480.
  팔 앞쪽에 있어서 팔을 세워 둔 대기 자세(PARK)에서는 팔이 큐브보다 화면 뒤쪽에 있다.
  (실제 책상이라면 한 번 보정해서 카메라 자세를 구하면 된다.)
- 무작위 배치: 반지름 0.16~0.26 m, ±55°, yaw ±45°, 큐브 중심끼리 최소 70 mm.
- 쌓는 곳: 맨 아래 큐브는 제자리에 둔다. 순서는 `--order` (기본 `red,yellow,blue`, 아래→위).

## 5. 인식 (OpenCV만)

**색 마스크** (렌더 측정값, OpenCV H 0~180):

| 색 | 실측 H | 범위 |
| --- | --- | --- |
| 빨강 큐브 | 0~3 | 0~6, 170~180 |
| 노랑 큐브 | 28 | 26~35 |
| 파랑 큐브 | 114 | 100~128 |
| **팔(노란색 출력물)** | 23~25 | — (노랑 범위 밖) |

S ≥ 120, 열림 1회 + 닫힘 2회, `cube_like`로 모양 필터(solidity ≥ 0.75), 색마다 가장 큰 후보.

**로봇 자기 가림 (노란 팔 대책, 2중):**
1. 색상 범위를 26부터 시작해서 팔(24)을 뺀다.
2. 고정 카메라: 책상 위 투영점이 팔 받침에서 11 cm 안쪽인 픽셀은 무시한다 (카메라가 안 움직이니 한 번만 계산).
   손목 카메라: 시작할 때 팔을 세워 **카메라가 하늘을 보게** 하고 그리퍼 4단계(열림~닫힘)에서
   색이 진한 픽셀을 모아 "집게 마스크"를 만든다. 검출할 때 현재 그리퍼 각도에 가까운 마스크 두 개를 뺀다.
   (테스트: 노랑 범위를 20~35로 일부러 넓혀도 집게가 노랑으로 잡히지 않음)

**픽셀 → 책상 좌표:** 카메라 자세를 알기 때문에 실루엣 픽셀마다 광선을 쏴서 높이 z 평면과
만나는 점을 구한다. 바닥 큐브는 z = 0.5·s, n층 위 큐브는 z = (n+0.5)·s. 중심 = 교점 평균,
yaw = 교점 윤곽의 `minAreaRect` (±45°로 접음).
- 고정 카메라 정확도 (30배치·90개): 위치 평균 0.6 mm·최대 1.8 mm, yaw 최대 5.5°
- 완성된 탑을 고정 카메라로 보면 맨 위 큐브는 ~1 mm로 정확하지만, 아래 큐브는 옆면만 보여서
  카메라 쪽으로 ~14 mm 치우치거나 아예 가려진다 → 최종 확인 규칙(§6)에 반영.

## 6. 동작 (상태 기계, `Stacker.run()` 제너레이터)

```
calibrate → 팔을 세워 손목 카메라로 하늘을 보며 집게 마스크 학습
look      → PARK 자세에서 고정 카메라로 3색 지도
for 큐브 in 순서[1:]:
    pick  → 큐브 위 6 cm, 손목 카메라로 보정 (지도에서 15 mm 안쪽일 때만 받아들임)
            → 내려가서 집기 → 끝까지 닫히면 '놓침' → 들기(10 cm) → 그리퍼 부하 + 손목 영상 속 색 위치로 확인
            → 실패하면 다시 look, 최대 3회
    place → 탑 위 8 cm → 6 cm → 탑 윗면 +2 mm까지 천천히 → 집게를 천천히 염 → 6 cm 올라감
            (집은 큐브는 고정 집게에 붙어 있으므로 그 오프셋 FIXED_JAW_X − s/2를 빼서 목표를 잡음,
             집게 방향 = 탑 꼭대기 큐브 yaw → 면이 맞춰짐)
    check → 빈 집게로 탑 위에서 손목 카메라: 새 색이 (층+0.5)s 평면에서 아래 큐브와 ≤ 6 mm
            → 통과하면 그 큐브가 새 "탑 꼭대기" (다음 놓을 기준)
실패 시 → 처음부터 다시 look (최대 2회, 이미 쌓인 큐브는 탑 위에서 확인하고 건너뜀)
final     → PARK, 고정 카메라: 맨 위 색이 탑 위치 ±12 mm, 아래 색은 자기 층 평면에서 25 mm 안쪽이거나 가려짐
            → 통과 "stacked", 아니면 "failed"
```

**심판:** 끝나고 2초 기다린 뒤 실제 큐브 위치로 층 높이 ±4 mm, 수평 ≤ 6 mm, yaw ≤ 10°를 확인하고,
로봇 판단과 비교한다.

## 7. 실행

```bash
mjpython simulator/cube_stack/stack_sim.py                     # 창, 무작위 배치 반복
mjpython simulator/cube_stack/stack_sim.py --once --seed 3 --order blue,red,yellow
python   simulator/cube_stack/stack_sim.py --headless --sheet stack.png
python   simulator/cube_stack/stack_sim.py --headless --trials 50 --quiet
```
창: 3인칭 화면(메인) + 오른쪽 위 고정 카메라(검출 윤곽 표시) + 그 아래 손목 카메라 + 단계 텍스트.

## 8. 테스트 (`pytest simulator/cube_stack/tests`, 약 4초)

| 테스트 | 내용 |
| --- | --- |
| 고정 카메라 정확도 | 10배치에서 3색 모두 찾고 위치 < 4 mm, yaw < 6° |
| 세워 둔 노란 팔 | 노란 큐브가 없으면 노랑을 찾지 않음 |
| 집게 마스크 | 노랑 범위를 넓혀도 집게를 노랑으로 보지 않음 |
| 쌓기 2가지 | 시드·순서 2가지 조합에서 심판 기준 성공, 로봇 판단도 성공, 60초 이내 |
| 무너짐 알아채기 | 다 쌓은 뒤 맨 위 큐브를 치우면 최종 확인이 "failed" |
| 정답 안 보기 | `stacker.py`/`eye.py`/`colors.py`가 큐브 실제 위치·qpos·referee를 쓰지 않음 (AST 검사) |
